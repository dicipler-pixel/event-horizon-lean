# READING RULES (Phase 1 recovery of Jeromie Beasley's black-hole work)

You are a reader, not a judge. The whole purpose is to stop DRIFT: earlier recoveries wandered from what the papers actually say.

1. Read every assigned file IN FULL with the Read tool (chunks with offset/limit for long files; keep going to the last line). Do not skim, do not sample, do not rely on grep alone. If a file is binary (png, npz), say so and record only its name and size.
2. Run NO tests, NO scripts, NO computations. Do not use the web. Do not modify, move or delete any file outside your own ledger file.
3. Record what each file SAYS, in its own wording. Quote key statements verbatim (short quotes) with their location: file path plus section/equation/theorem number or line number.
4. Grades stay exactly as the source gives them (e.g. theorem, proposition, proved, checked, gated, reading, conjecture, ansatz, hypothesis, open, withdrawn). Never upgrade or downgrade. If the source gives no grade, write "no grade given".
5. Do not call anything dead, wrong or unsupported yourself. If the SOURCE withdraws or kills something, record that with the source's words and location.
6. For multiple versions of the same document: read the earliest fully, then every later version fully, and list for each version (a) what it adds, (b) what it drops, (c) what it changes in wording, numbers or grade, and (d) what it holds that NO other version holds.
7. List every place where two versions or two files DISAGREE (a number, a sign, a grade, a definition, a claim), with both locations. Do not resolve disagreements.
8. Record every named result, equation of substance, numeric value, check/gate name with its stated outcome, figure, citation, and every open question the source itself lists.
9. If you could not read something in full, say exactly what and why. Never claim a full read you did not do.
10. Write your ledger as Markdown to the path given. It should be LONG and complete, not compressed. Structure: one section per file (path, title, date/version, size, read-in-full yes/no), then contents, then a final "Disagreements" section and a "Not read / problems" section.
11. Your final message back: 10 lines max: ledger path, number of files read in full, anything not read, the top disagreements.
